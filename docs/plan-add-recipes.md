# План: 36 рецептов, подготовка ингредиентов, 13 станций

## Задача

Сейчас в игре один рецепт (бургер из 7 слоёв) и 8 станций. Механики готовки нет
вообще: повар приходит на полку, берёт ингредиент уже «готовым», относит на
раздачу. Расширяем до 36 рецептов (бургеры, пицца, хотдоги, супы, салаты, паста,
сэндвичи, завтраки) и вводим подготовку: жарка, нарезка, замес теста, выпечка,
варка.

## Модель

### Предметы делятся на три класса

- **сырьё** — берётся со станции-полки как есть;
- **полуфабрикаты** — результат преобразования на станции;
- **блюда** — результат финишной станции, уходит на кассу.

### Цепочки подготовки

`PREP: Record<Полуфабрикат, { from, at, at: StationType }[]>`. У полуфабриката
может быть несколько шагов, цепочка разворачивается в линейный маршрут «полка →
станция → станция → раздача». Примеры:

- `chopped-tomato ← tomato @ cutting-board`
- `patty ← patty-raw @ grill`
- `hot-broth ← broth @ stove-pot`
- `tomato-sauce ← chopped-tomato @ stove-pot`
- `dough ← flour @ dough-mixer`
- `pizza-base ← dough @ pizza-oven`
- `toast ← bun @ pizza-oven`

Станции объявляют, что умеют преобразовывать, и сами решают результат — без
хардкода преобразований в системах.

### Порядок слоёв

Флаг у рецепта:

- `layered` — бургер, пицца, хотдог, сэндвич: слои строго по порядку;
- `assorted` — суп, салат, омлет: повар сам выбирает, что нести следующим.

### Финишная станция

У рецепта поле `finishAt`. Станция объявляет, какие типы блюд доводит:

| Станция           | Типы блюд                          |
| ----------------- | ---------------------------------- |
| `pizza-oven`      | pizza, bruschetta                  |
| `grill`           | burger, hotdog, sandwich, omelette |
| `stove-pot`       | soup, pasta, rice                  |
| `serving-counter` | salad, shawarma                    |

Когда все слои выложены, повар идёт на `finishAt` и одним действием превращает
стопку в готовое блюдо. Стек — это `order.placed`, в руках ничего не лежит,
отдельного шага «поднять стопку» нет.

Для супов слои кладутся сразу в кастрюлю (`stove-pot` вместо раздачи) и `finish`
происходит там же без перехода. Для пиццы слои собираются на раздаче, потом
повар идёт в печь.

Существующий `take-burger` становится этим обобщённым действием.

## Бейдж: атлас вместо эмодзи

Сейчас предмет в руках рисуется эмодзи через `src/assets/carry-emoji.ts` (рендер
каждого эмодзи в `CanvasSource` 32 px). Планируется заменить на спрайты из
атласа ингредиентов.

Нужно подготовить атлас: 57 иконок предметов (28 сырья + 18 полуфабрикатов + 11
блюд), единый размер кадра, `frame`-индексация по id предмета. Заодно уходит
проблема `badgeSignature`: она битовая и влезает в 32 бита только пока предметов
меньше 128; при появлении в бейдже названия блюда 32 бит уже не хватит, и
подпись проще сделать строкой.

Пока атласа нет — рисуем эмодзи, задачу переключения держать в бэклоге.

## Известные ограничения

- 13 станций не влезают в текущую раскладку 4+4: `tests/field.test.ts` запрещает
  ставить станции в зоне блуждания поваров и проверяет отсутствие наездов на
  пяти разрешениях от 800×600. Нужно либо скейлить спрайты станций и делать 6
  рядов, либо сдвигать `WANDER_AREA` и делать 3 колонки.
- Средняя длина заказа вырастет с 7 до 15–18 действий. Замеряем после того, как
  заработает.
